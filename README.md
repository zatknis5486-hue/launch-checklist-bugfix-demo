# Launch Checklist: a reproducible before/after bug-fix demo

> **Self-created technical demo, not client work.** This repository was built on purpose to
> show how a common React bug is found, fixed and locked down with a regression test. The bug
> was planted deliberately; it is not taken from anyone's codebase and no client was involved.

The app is a single-page "Launch Checklist": a founder's pre-launch tasks (synthetic seed data,
e.g. "Set VITE_SUPABASE_URL in Vercel project settings", "Enable RLS on profiles table") with a
search box, an All / Open / Done status filter, a checkbox per task and visible/open counts.
No backend, no network calls, no analytics, no API keys, no third-party CDN assets.

**What changed, in one line:** the filtered task list was a copy kept in `useState` and synced by a
`useEffect` whose dependency array only listed `[tasks]`, so typing in the search box or changing
the status filter did nothing; the fix derives the list with
`useMemo(() => filterTasks(tasks, query, status), [tasks, query, status])` and adds the tests
that would have caught it.

The full write-up is in [`case/CASE_STUDY.md`](case/CASE_STUDY.md); the same facts in machine-readable
form are in [`case/case.json`](case/case.json). Both are generated by `npm run case:build`. The
before/after screenshots it shows live in `case/screenshots/` and are captured from this app by
`npm run case:screenshots`.

## Stack

Vite, React 19, TypeScript, Vitest, Testing Library, ESLint with `eslint-plugin-react-hooks`.
Exact versions: see `package-lock.json` or the `stack` field of `case/case.json`.

## Run it

Requires Node 20.19+ or 22.12+ (Vite 7's minimum) and npm. Built and verified with Node 24.

```sh
npm install
npm run dev        # dev server, prints a localhost URL
npm run build      # typecheck + production build into dist/
npm run preview    # serve dist/ locally
```

To see the bug yourself: `git checkout demo-bug`, then `npm run dev`, type `redirect` into the
search box and notice that nothing filters until you tick a checkbox. `git checkout main` brings
you back to the fixed version.

## Test it

```sh
npm test           # vitest run: unit tests for filterTasks + UI regression tests
npm run typecheck  # tsc -b
npm run lint       # eslint . (on the demo-bug commit this prints the exhaustive-deps warning)
```

## Prove the regression

```sh
npm run prove
```

`scripts/prove-regression.mjs` finds the non-test files under `src/` that differ between the
`demo-bug` and `demo-fix` tags, temporarily writes the `demo-bug` version of each into the working
tree, runs the test suite from `HEAD` against it (expected: the regression tests fail), restores the
files with `git checkout --` in a `finally` block (on completion or error), and runs the suite again
(expected: pass). It exits 0 only if the first run failed and the second passed.

Each run is judged from Vitest's JSON report (written to `case/.tmp/`, gitignored), not from the
exit code alone: run 1 counts as failed only if at least one test failed and no test file failed to
load; run 2 counts as passed only if every collected test passed. A crash, an import error, a
missing report or a Vitest process that is killed (it is given 10 minutes) is reported as an
`ERROR` and never counts as proof. It refuses to start if any of the files it would touch has
uncommitted changes, so it cannot destroy work in progress. It does not undo anything on start: if
an earlier run was interrupted in a way the `finally` block could not survive (a hard kill), the
refusal message prints the exact `git checkout -- <paths>` command that discards the leftover bug
version, and the same command is printed whenever the restore itself fails.

If `git` is not on your `PATH` (for example a portable Git on Windows), point the script at it:

```powershell
# Windows PowerShell
$env:GIT_EXE = "C:\path\to\git.exe"; npm run prove
```

```sh
# bash / zsh
GIT_EXE=/path/to/git npm run prove
```

The same variable is honoured by `npm run case:screenshots` and `npm run case:build`.

## Capture the screenshots

```sh
npm run case:screenshots
```

`scripts/capture-screenshots.mjs` produces the three images the write-up shows, from this app, with
nothing downloaded: it uses a Chrome or Edge that is already installed (found in the usual locations,
or set `CHROME_EXE` to the executable) in headless mode, driven over the Chrome DevTools protocol with
Node built-ins only. Like the proof, it temporarily writes the `demo-bug` version of `src/App.tsx` into
the working tree (refusing if the file has uncommitted changes, restoring it in a `finally` block),
starts the Vite dev server on a free port, clicks the search box, types `redirect` key by key and
captures the app area; ticks the one matching task's checkbox and captures again (the stale filter
suddenly applies); then restores `src/App.tsx` and repeats the typing on `HEAD`. Before every capture
it reads the summary line and the task rows from the DOM and refuses to write an image whose page
state is not the one the write-up describes.

It writes `case/screenshots/before-typed.png`, `before-after-toggle.png`, `after-typed.png` (the
`main.app` element at a 1024px-wide viewport, light colour scheme, 2x device scale) and
`manifest.json`: browser version, viewport, the commit each image was taken from and the text read from
the page. `npm run case:build` merges the manifest with the captions in `scripts/case-content.mjs` and
refuses to build when an image, its size or its commit no longer matches the repository. Commit the
images and the manifest together with the regenerated case files.

## Rebuild the case write-up

```sh
npm run case:build
```

`scripts/build-case.mjs` reruns the proof, trims both test outputs (ANSI codes removed, local paths
replaced by `<repo>`, timings replaced by `<time>`, `<elapsed>` and `<n>ms`), takes the real
`git diff demo-bug demo-fix -- src` with test files excluded, reads both commit hashes and messages,
reads the installed versions of the stack, runs ESLint on the `demo-bug` version of the changed file,
and writes `case/case.json` and `case/CASE_STUDY.md`. Its sanity checks use the same parsed Vitest
reports as the proof. `generatedAt` is a date (`YYYY-MM-DD`), so running it twice on the same history
rewrites both files byte for byte and leaves `git status` clean. The narrative text (summary, symptom,
root cause, lesson, screenshot captions) lives in `scripts/case-content.mjs`; edit it there and rerun.
The screenshot section takes its facts (size, commit, the summary line read from the page) from
`case/screenshots/manifest.json`, written by `npm run case:screenshots`; see above.

It writes nothing if the proof does not hold. It also refuses when the non-test files under `src/`
at `HEAD` differ from the `demo-fix` tag, because the diff in the write-up is tag-to-tag while the
"after" test run is measured on `HEAD`, and the two would then describe different code. Re-point
`demo-fix` (see "Before publishing") or, if the drift is intended, pass the flag through npm:

```sh
npm run case:build -- --allow-head-drift
```

With the flag, `case.json` gains `"headMatchesFixTag": false` and `CASE_STUDY.md` carries a visible
note; neither appears when `HEAD` matches the tag.

## Repository layout

```
index.html                   Vite entry
src/main.tsx                 React root
src/App.tsx                  state, filtering (the file the fix changes), layout
src/components/              SearchBox, StatusFilter, Summary, TaskList
src/data/seedTasks.ts        synthetic seed tasks
src/lib/filterTasks.ts       pure filter helper
src/lib/filterTasks.test.ts  unit tests for the helper
src/App.test.tsx             UI regression tests (fail on demo-bug, pass on demo-fix)
src/setupTests.ts            registers jest-dom matchers
scripts/prove-regression.mjs runs the suite against the bug source, then HEAD
scripts/capture-screenshots.mjs  captures case/screenshots/*.png from the running app (headless Chrome/Edge)
scripts/build-case.mjs       generates case/case.json and case/CASE_STUDY.md
scripts/case-content.mjs     human-written narrative and screenshot captions used by build-case
case/case.json               machine-readable case (generated)
case/CASE_STUDY.md           human-readable case study (generated)
case/screenshots/            before/after PNGs and manifest.json (generated by case:screenshots)
case/.tmp/                   Vitest JSON reports from the last proof run (gitignored)
eslint.config.js             ESLint 9 flat config with react-hooks rules
vite.config.ts               Vite + Vitest config (jsdom, setup file)
```
